# Проверка поставки — 03.10.2026

- Production Node-сборка (`node scripts/build_server.mjs`) успешно собрана.
- TypeScript: `tsc --noEmit --incremental false` без ошибок.
- Полный регрессионный набор: 206/206 до добавления отдельного теста daemon.
- Дополнительный набор server runtime + daemon + integration: 7/7, в том числе
  отдельный тест параллельного сопровождения при зависшем сканировании.
- Интеграционный тест запускает настоящий production HTTP-сервер на свободном
  loopback-порту, использует временную базу, проверяет авторизацию страниц/API,
  CSRF, сохранность после перезапуска и целостность backup. Порт 3000 и база
  действующего терминала не использовались.
- Серверные настройки не принимают пустые/шаблонные секреты или публичный HTTP.
- Runtime SQLite и секреты не попадают в Docker build context по allowlist.
- Исходники стратегий и вычисления TP/SL не изменены.
- Проверка исходников на известные локальные секреты, типовые токены, приватные
  ключи и литералы credentials не нашла совпадений. Это не заменяет будущий
  security review публичного развёртывания.

Не проверено: Docker Engine/Compose на Linux (Docker отсутствует на компьютере),
длительная работа 24/7, reboot целевого сервера, публичный TLS reverse proxy,
доступность биржевых провайдеров из сети сервера. До этих проверок поставку
использовать как кандидата для серверного PAPER-теста, не для реальных средств.

Известные старые ограничения остаются: пробелы минутной истории после простоя,
неатомарные участки торгового учёта вне `db.batch`, неполнота теневой статистики,
зависимость скальпинга от открытой вкладки. Docker не исправляет эти ошибки.
Нельзя включать масштабирование/несколько реплик с одной базой.
