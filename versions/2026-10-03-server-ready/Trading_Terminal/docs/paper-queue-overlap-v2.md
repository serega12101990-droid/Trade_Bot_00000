# Автовход paper: очередь READY и пересечения позиций

Дата: 10 сентября 2026. Версия исполнения: `ready-queue-overlap-v2`.
Модель прогнозов `scenario-v1.6.0` и политика `selective-paper-v1` не изменены.

## Что подтверждено

Две позиции SNGSP LONG 4h из журнала:

| Сигнал (МСК) | Расчётный вход | Цена | Выход по SL (МСК) | PnL с комиссиями |
| --- | --- | --- | --- | --- |
| 09.09 07:00 | 09.09 11:00 | 42,37 | 10.09 12:00 | −1 627,03 ₽ |
| 09.09 23:00 | 09.09 23:50 | 41,99 | 10.09 12:01 | −1 049,81 ₽ |

Вторая позиция появилась в базе лишь 10.09 в 14:50:07. Первая к этому времени уже числилась закрытой, хотя интервалы владения пересекались. Проверка только текущих `OPEN` повторно предоставляла лимит по инструменту.

В старой очереди сначала выбирались 500 старейших прогнозов, затем в JavaScript отбрасывались неготовые. Перед вторым READY в момент его записи находились 635 более ранних неотработанных строк: он не попадал в пакет. Это техническая задержка обработки, а не рыночный фильтр.

SL и два исторических убытка не переписывались. Проверка новой функции на резервной базе вернула для второй позиции `OVERLAP` с первой. Это контрфактическая проверка допуска, не новый расчёт доходности всей стратегии. Первый вход этими исправлениями не отменяется.

## Новые правила исполнения

1. Актуальная модель, READY, разрешение текущей политики, направление и срок проверяются в SQL **до LIMIT 500**. Повреждённый JSON не прерывает очередь. Стратегические требования не ослабляются.
2. Уже открытые позиции сначала оцениваются по минутной истории. История одного инструмента повторно используется в рамках прохода; закрытие и PnL не проводятся второй раз.
3. Автокандидат проверяется на пересечение с записанными OPEN/CLOSED позициями того же счёта, рынка и инструмента, включая иной ТФ и противоположную сторону. При подтверждённом пересечении новый полный объём не выделяется. Ни знак, ни величина прошлого PnL не участвуют в решении.
4. Если прошлую открытую позицию ещё нельзя проследить до времени нового входа, кандидат остаётся в ожидании истории, а не объявляется проигравшим. Когда предыдущая сделка подтверждённо закрыта до нового входа, следующий самостоятельный эпизод допустим.
5. Время выхода по свечам означает начало свечи. Для оценки пересечений капитал освобождается только после её окончания. При неизвестной точности старого выхода консервативно используется весь базовый ТФ; ручные временные отметки считаются точными.
6. При запоздалом восстановлении более раннего сигнала его плановый интервал до `due_time` также не должен пересекать уже записанную более позднюю позицию. Это консервативная защита: мы не предполагаем, что гипотетическая сделка успела бы закрыться раньше.
7. AUTO имеет единственный путь входа — по цене закрытого сигнала с проверками. Ожидающий автоматический кандидат не может перейти в старую ручную ветку по текущей котировке. Истёкшие кандидаты не открываются вновь.

## Журнал и статистика

- Повторный сигнал не удаляется: paper-строка получает `SKIPPED / OVERLAPPING_EXPOSURE`, подробность содержит ID пересекающейся позиции и версию исполнения.
- Сам forecast сохраняется. После его оценки результат доступен через существующую теневую статистику пропусков, не как состоявшаяся балансовая сделка.
- При запоздалой записи UI отдельно показывает «В журнале с». Это `created_at` записи кандидата, **не** подтверждение фактического времени открытия биржевого ордера.
- В существующие SL/TP, объёмы, комиссии, результаты и баланс исторических сделок изменения не вносятся. Автоматическое сопровождение уже открытых позиций продолжается штатно.
- Новые записи помечены `ready-queue-overlap-v2` в деталях входа/отказа. Для сравнения качества исполнения нужно разделять эту версию и предыдущие записи, даже если модель прогноза совпадает.

## Границы исправления

Это не фильтр «плохих направлений», не обещание роста винрейта и не сужение стопов. Ручное добавление к позиции, если оно явно запрошено пользователем, не отключалось. Полный хронологический пересчёт общего капитала по всем инструментам не реализован: текущие портфельные лимиты сохранены. Механизм рассчитан на существующего единственного локального исполнителя; распределённая блокировка нескольких серверов — отдельная задача. Доступность и задержка внешней минутной истории этим патчем не исправляются.

## Проверка и откат

`tests/paper-queue-overlap.test.mjs`: SQL-пагинация, повреждённые данные, обе стороны/разные ТФ, прибыльный и убыточный повтор, неполная история, точность выхода, повторный вызов без повторного PnL, полный цикл исполнения на SQLite в памяти, AUTO/MANUAL и истечение срока. Реальные торги тестами не запускаются.

У двух старых тестов `forecast-shadow-risk` зависимость от календарной даты воспроизведена на резервной версии. Их часы зафиксированы на дату сценария; добавлена отдельная проверка истечения срока восстановления истории. Торговый код теневой лаборатории не менялся.

Резерв до правок: `backups/releases/2026-09-10_PRE_PAPER_QUEUE_OVERLAP/`. Там исходники, архив, согласованная копия SQLite и инструкция восстановления. На сервер и GitHub эти изменения не отправлялись.

Итог проверки: **200/200 тестов прошли**, включая 13 проверок очереди/пересечений. TypeScript и production-сборка прошли. ESLint: 0 ошибок, 5 существовавших предупреждений вне изменённой логики. Локальные `/` и `/api/paper-trades` ответили HTTP 200 без принудительного запуска оценки. Значения обеих исторических SNGSP в ответе API совпали с резервом.
