# План разработки

## Этап 1. Формализация

- [ ] Заполнить паспорт первой стратегии.
- [ ] Собрать примеры правильных и неправильных входов.
- [ ] Определить рынки, рабочие таймфреймы и ограничения риска.
- [ ] Зафиксировать объективный алгоритм построения 4H-канала.

Критерий готовности: два человека одинаково размечают один график по записанным правилам.

## Этап 2. Общее ядро

- [ ] Отделить получение свечей от торговой стратегии.
- [ ] Отделить риск, позиции и исполнение ордеров.
- [ ] Добавить идентификатор стратегии и версии к каждому сигналу и ордеру.
- [ ] Записывать причины всех разрешённых и отклонённых входов.

## Этап 3. Данные и Backtest

- [ ] Хранилище завершённых свечей и биржевых исполнений.
- [x] Свечной event-driven бэктестер EMA Corridor без look-ahead bias.
- [x] Комиссии и slippage на обеих сторонах сделки.
- [ ] Исторические bid/ask spread и funding.
- [ ] Replay одной сделки свеча за свечой.
- [x] Базовый отчёт: win rate, TP rate, PF, expectancy, MFE/MAE, drawdown и причины отказа.
- [ ] Сравнительные отчёты по инструментам, режимам рынка и паттернам.

## Этап 4. Первая стратегия

- [ ] Дневной режим Элдера.
- [ ] Подтверждённый канал 4H.
- [ ] Зоны входа и запрета внутри канала.
- [ ] Триггеры Ниссона на 15m/30m.
- [ ] Динамические SL, TP1, TP2 и сопровождение.

## Этап 5. Paper и DEMO

- [ ] Paper trading на живых данных.
- [ ] Сверка расчётной и фактической цены.
- [ ] Защита от дублей и потери связи.
- [ ] Контролируемый запуск Bybit DEMO.

## Этап 6. Приложение

- [ ] Dashboard состояния рынка и бота.
- [ ] Интерактивный график с каналами, зонами и сделками.
- [ ] Журнал сигналов и причин отказа.
- [ ] Сравнение стратегий и версий.
- [ ] Настройки риска и уведомления.

## Этап 7. Расширение

- [ ] Подключаемые стратегии без изменения торгового ядра.
- [ ] Отдельный модуль и сравнительный тест стратегии `EMA Gap / EMA Corridor`.
- [x] Первый фиксированный out-of-sample тест 70/30 для EMA Corridor.
- [ ] Полный walk-forward на нескольких временных окнах.
- [x] Выбор профиля только по train без использования контрольных 30%.
- [ ] Дополнительный контроль переоптимизации на новых периодах и инструментах.
- [ ] Live только после отдельного решения и прохождения критериев допуска.
